# 🎵 MUME Audio System Refactor Blueprint

## 🎯 Goal
Consolidate the fragmented audio logic into a single, data-driven service that uses a non-React manager for WebAudio operations. This will resolve synchronization issues and reduce the audio codebase by ~70%.

## 🏗️ Target Architecture

### 1. Data Layer: `src/constants/audioManifest.ts`
Move all hardcoded logic, BPMs, and URLs into a structured manifest.
```typescript
export const AUDIO_MANIFEST = {
  ambient: {
    terrains: {
      'FOREST': { url: '/assets/Sounds/Terrain Sounds/forest.mp3', volume: 0.25 },
      'SHALLOWS': { url: '/assets/Sounds/Terrain Sounds/shallows.wav', volume: 0.8 },
      // ... etc
    },
    zones: {
       'lorien': { day: '/assets/Sounds/Zone Sounds/Lorien1.mp3', night: null, bpm: 100 },
       // ... etc
    }
  },
  effects: {
    'slash': '/assets/Sounds/Sound effects/slash.mp3',
    'bash': '/assets/Sounds/Sound effects/bash.mp3',
    // ... etc
  }
};
```

### 2. Service Layer: `src/services/audio/AudioManager.ts`
A singleton class that manages the `AudioContext`.
- **Method**: `playEffect(name: string, options?: PlayOptions)`
- **Method**: `setAmbient(type: 'terrain' | 'zone', key: string)`
- **Logic**: Handles its own cross-fading and buffer caching internally.

### 3. Hook Layer: `src/hooks/useAudioSystem.ts`
Two lean hooks that replace all others:
- `useAmbientController()`: Subscribes to `RoomStore` (terrain/zone) and `MumeTime` (day/night). Calls `AudioManager.setAmbient()` when state changes.
- `useAudioEffects()`: Returns methods to play one-shots (e.g., `playHit()`).
